The root AGENTS.md is the routing/operating entrypoint, not a replacement for specialist requirements.

Authority is *domain-specific*: an approved host business requirement owns business behavior, an approved API contract owns API behavior, official Spec Kit owns `.specify/` and `specs/`, the source tree describes observed implementation, test logs describe observed evidence, and handoffs record continuity only. S2C configuration cannot approve a requirement.

Use observed files and explicit provenance to identify authorities. If authoritative documents conflict, or an approval is missing, report NEEDS_REVIEW/BLOCKED instead of synthesizing a decision. Refer only to observed, in-repository paths. Never treat inferred schema, placeholders, cached state or historical handoffs as approved current truth.

Every human-governed document has a clear owner, version/revision where relevant, approval evidence when required and links to affected tasks. Do not overwrite user-owned AGENTS, requirements, workflow rules or legacy handoffs. S2C machine journals are distinct from human handoffs.

## PLAN-081 subject authority and conflict handling

For each task, name the **subject** and the source that owns the corresponding decision. A host business document cannot silently relax a host security policy; a Spec Kit plan cannot approve an unspecified business requirement; implementation source can show behavior but not authorize it; a test result can show an outcome but not waive a requirement. AGENTS describes how the agent should operate but does not replace approved contracts. An optional host policy map is routing metadata, not a signed decision.

Required provenance for important decisions: observed repository-relative path and revision, responsible owner, exact section/requirement ID, known approval status, affected task/AC, and conflicting evidence where applicable. If ownership or approval is unknown, stop the affected write and escalate through the [agent roles](../.workflow/agentRoles.md); do not fill blanks with historical handoffs or sample templates.

Never import this development repository's governance documents into an installed host as the host's requirements. Keep host root/nested AGENTS, official Spec Kit artifacts, and S2C-generated `.agents/state/`, `.agents/.handoffs/`, `s2c/` in their separate namespaces.
