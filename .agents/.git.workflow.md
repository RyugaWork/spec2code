# Universal Git workflow — PLAN-080

S2C is a repository-local assistant skill, not a GitHub account manager or autonomous Git client. The host repository's Git and contribution policies take precedence for host tasks.

1. Validate the exact physical Git worktree and inspect local status/branch before changing files.
2. Preserve third-party changes. Do not reset, clean, stash, rebase, merge, force-push, create branches, or run remote Git operations without explicit task authorization.
3. Stage only reviewed in-scope paths. Never auto-stage .env, credentials, generated state or external artifacts.
4. Use the repository's commit conventions; this S2C development repository prefers Conventional Commits.
5. Do not infer reviewer approval from a handoff, a Git commit, a policy map, a workflow state file, or an AI response.
6. Record exact validation evidence, changed paths, risks and rollback instructions. A passing build is not a security signoff.

This document is a development policy for Spec2Code itself; installations must not overwrite host Git governance.
