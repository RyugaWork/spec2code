## PLAN-083 — STOP, state snapshot and resumable workflow handoff (2026-11-13)

- **Status:** IN PROGRESS. Documentation/agent protocol, not yet a new Python Workflow Guard transition or autonomous background runner.
- **Requirement:** the agent must be able to stop a task without falsely completing it, capture its exact last-known state and produce a reproducible human-readable handoff so another human/agent can safely resume after revalidation.
- **Authoritative spec:** `.agents/.workflow/workflowSpecification.md`, `.agents/.workflow/stopAndHandoff.md`, and `.source/references/stop-handoff-template.md`. Map new F37 and S2C-REQ-037 in `.agents/.traceMatrix.md`; add cross-cutting NFR-007 for fail-safe pause/resume.
- **Triggers:** explicit user STOP/PAUSE/handoff, missing authorization or policy, scope/root violation, high-risk uncertainty, source drift, failed validation, tool outage, context/time boundary or interruption. State snapshots must distinguish observed current evidence, claimed previous results and unknown facts.
- **Safe stop:** immediately cease new mutations; if root/scope safe and explicitly authorized, collect read-only current status/diff and optionally checkpoint an already-active local session (a checkpoint is a write), then write a separate manually owned STOP handoff. If unsafe or unavailable, emit the handoff in-chat with `NOT_PERSISTED`. No silent session finish/merge, Git commit/push, new permission or workflow COMPLETE.
- **Resume gate:** restore authority by re-reading root/nested AGENTS and current spec, revalidate the exact checkout/ref/task/scope, inspect session and source drift, re-evaluate invalidated plan/verify evidence and obtain any missing external approvals. A prior handoff cannot self-authorize.
- **Acceptance:** STOP handoff has task/session/ref, last phase, stop reason, observed changed paths, uncommitted/external attribution, tests with source revision and outcome, pending requirements/AC IDs, blockers/approvals, safety/rollback, next action and explicit persistence flag; no secrets. Multiple stops are versioned without overwriting; a failed write still returns an in-chat handoff.
- **Gaps:** current `workflow_guard.py` supports begin/advance/invalidate/reconcile/close but no `pause` or `resume` action; `session_guard.py` provides status/checkpoint/finish but checkpoint does not complete/close. STOP is an **agent-level documentation contract** only until a separately scoped runtime patch and tests are approved. PR #7's P0/P1 defects remain open.
- **Validation:** check documented CLI flags against actual Python, Markdown links against Git tree, feature-to-RTM completeness, source/test naming, exact-head CI and review. Do not claim an end-to-end runtime STOP test before one exists.
- **Rollback:** revert only PLAN-083 and RTM/docs changes; preserve all prior handoff/session contents. Do not auto-merge PR #8 or parent PR #7.
