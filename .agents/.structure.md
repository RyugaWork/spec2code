## Installed host layout — intentionally distinct

```text
target-git-project/
├── AGENTS.md                      # Host governance, never overwritten implicitly
├── .agents/
│   ├── skills/spec-to-code/
│   │   ├── SKILL.md
│   │   ├── scripts/
│   │   ├── references/
│   │   └── .config/
│   ├── state/                     # Host-local Spec2Code session state
│   └── .handoffs/                 # Host-local session logs + merge ledger
├── s2c/                          # Architecture root/layer/function documents
├── .specify/ and specs/           # Only official Spec Kit owns these
└── src/, app/, backend/, ...      # Actual application source
```

No application-specific fixed `.source/` directory is required in a target checkout. `.agents/.handoffs/` in this *development repo* is documentation; target `.agents/.handoffs/` contains session runtime logs and ledger, while `s2c/` contains generated architecture indexes. Historical `.summerize.md` spelling stays for compatibility.

## Layout migration policy
Do not auto-migrate a running host session, overwrite a host-owned file, or merge runtime and governance JSON. Copies to installed skill folder must preserve `.source/.` contents (including hidden `.config/`).

## Target checkout output contract (PLAN-071)

Host session state remains `.agents/state/`. Host session handoff logs and verified merge ledger are under `.agents/.handoffs/`, while generated architecture documents are under `s2c/`. These runtime outputs are distinct from version-controlled development governance files under this source repository's `.agents/`. The runtime refuses legacy data or unowned collisions until explicit review and migration.
