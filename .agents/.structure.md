# Spec2Code — Development and target-project structure v0.7.0

## Source repository layout

```text
spec2code/
├── AGENTS.md
├── README.md
├── pyproject.toml
├── .gitignore
├── .github/workflows/tests.yml
├── .agents/                       # THIS repository's governance only
│   ├── .config/                   # Agent governance metadata (no runtime secrets)
│   ├── .workflow/                 # Plan/code/test/handoff procedure
│   ├── .handoffs/                 # Versioned development change records + legacy docs
│   ├── .changelog.md
│   ├── .spec.md
│   ├── .features.md
│   ├── .checklist.md
│   ├── .plans.md
│   ├── .risk.md
│   └── .structure.md
├── .source/                       # Deployable skill sources
│   ├── SKILL.md
│   ├── scripts/
│   ├── tests/
│   ├── references/
│   ├── integrations/
│   └── .config/                   # Strict validated runtime JSON
└── docs/
```

## Installed host layout — intentionally distinct

```text
target-git-project/
├── AGENTS.md                      # Host governance, never overwritten implicitly
├── .agents/
│   ├── skills/spec-to-code/
│   │   ├── SKILL.md
│   │   ├── scripts/
│   │   ├── references/
│   │   └── .config/
│   └── state/                     # Host-local Spec2Code session state
├── .handoffs/                     # Host-local change tracking
├── .specify/ and specs/           # Only official Spec Kit owns these
└── src/, app/, backend/, ...      # Actual application source
```

No application-specific fixed `.source/` directory is required in a target checkout. `.agents/.handoffs/` in this *development repo* is documentation; target `.handoffs/` remains session runtime output. Historical `.summerize.md` spelling stays for compatibility.

## Layout migration policy
Do not auto-migrate a running host session, overwrite a host-owned file, or merge runtime and governance JSON. Copies to installed skill folder must preserve `.source/.` contents (including hidden `.config/`).
