# Continuous Scope Enforcement — Spec2Code v0.6.3

**Intent:** repeat scope verification at every relevant event and file access; avoid a background watcher or redundant full-repository scans. Path containment is a security boundary, not code-change authorization.

## Five boundaries

| Boundary | Enforced contract | Failure behavior |
|---|---|---|
| 1. Session | `start` stores physical worktree root, root inode/device and absolute Git admin dir; subsequent session operations and routing recheck them | `SCOPE_VIOLATION`; retain state for manual recovery |
| 2. Operation | Entrypoints validate the exact Git checkout; every source/cached/managed path is rechecked for traversal and symlink ancestors before access | `PATH_GUARD_BLOCKED`; no alternate-root fallback |
| 3. Write | On POSIX with `openat`-style support, write/read/append/unlink use directory handles and `O_NOFOLLOW`. Atomic writes use same-parent rename. Handoff deletion requires exact SHA-256 | Block unsafe target; preserve other session logs |
| 4. Commit | Context Router rejects a Git HEAD different from the last checkpoint; checkpoint invalidates any old local `context-pack.json` on HEAD or tracked-file changes | `STALE_GIT_HEAD` / context-pack invalidation; re-route task |
| 5. MCP | A trusted host configures a fixed root in `MCPWorkspaceBoundary`. Requests cannot pass their own root, request arbitrary shell, or elevate write rights. Write actions require a matching Session ID and fresh HEAD | `SCOPE_VIOLATION`; `checkpoint_session` remains the only write permitted to reconcile a changed HEAD |

## Files and ownership

- `scripts/path_guard.py`: `validate_root()`, `check_path()`, `capture_scope()`, `assert_scope()`.
- `scripts/scope_io.py`: internal filesystem IO. It assumes the enclosing CLI/MCP operation has already validated its Git checkout. **Never** expose low-level IO as an MCP tool independently of `MCPWorkspaceBoundary`.
- `scripts/mcp_boundary.py`: authorization only. **No actual MCP server, transport, credentials, or network listener** are supplied in v0.6.3.
- `.agents/state/session.json`: local checkout binding. Do not copy active state between clones or worktrees.
- `.agents/state/context-pack.json`: ephemeral cache, removed at a changed HEAD/trackable file checkpoint, then regenerated by the router.

## Security limits and migrations

1. This is *operation-based* validation, not continuous polling and not remote Git monitoring. It does not verify remote HEAD until an explicitly authorized fetch/API read occurs.
2. On Linux/compatible POSIX, anchored descriptor operations prevent symlink path escapes for managed writes even if an ancestor path is swapped after preliminary checks. A hostile user with permissions to mutate the **same checkout contents** can still race application-level operations; use OS sandbox/container/filesystem permissions to isolate untrusted tenants.
3. On Windows platforms without portable dir-fd/no-follow support, code repeats path validation but **does not guarantee TOCTOU protection**. Run in a trusted workspace or isolate using Windows ACLs and a dedicated OS identity.
4. Existing ACTIVE v0.6.2 sessions have no new binding and must be completed and merged with their matching version before migration. Do not erase state or fabricate an approval.
5. MCP is future integration. An MCP host must create a server-owned `MCPWorkspaceBoundary` per authorized worktree, authorize every request and independently enforce authentication, OAuth scopes, concurrency locks and user consent for writes.
6. Context packs use a short fingerprint of the checkout identity, **not** absolute home/Git paths. Session state remains local.

## Verification

```sh
python -m unittest discover -s tests -v
```

Regression tests cover cross-repository session reuse, root replacement, client-provided MCP roots, symlink escape, verified unlink, stale HEAD, and context-pack invalidation. These checks do not substitute end-to-end security testing on Windows, network mounts or a real MCP server.
